- **Layered Hexagonal Architecture**: The system is structured into distinct layers: `domain` (canonical types/ports), `brokers` (adapter implementations for Dhan/Upstox/Paper), `datalake` (Parquet/DuckDB storage), `analytics` (quantitative engines), and `cli/api` (entry points). 
- **Dependency Direction**: Enforced via `import-linter` contracts in `pyproject.toml`; the `domain` layer is strictly isolated, while `brokers.common` provides shared abstractions (OMS, resilience, event bus) without depending on specific broker implementations.
- **Unified Runtime & Composition**: `api_server.py` and `cli/main.py` act as composition roots, wiring the `TradingRuntimeFactory`, `BrokerService`, and `LifecycleManager` to manage background services like token refreshers and reconciliation engines.
- **Interface Boundaries**: Broker adapters implement the `MarketDataGateway` ABC defined in `brokers/common`, ensuring swapability. The `datalake` exposes a `ResearchAPI` and `DataLakeGateway` for consistent data access across CLI and API contexts.
