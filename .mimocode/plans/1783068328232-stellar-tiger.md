# Guardrails, Standards & Architecture Enforcement Plan

## Context

22 refactoring tasks completed (exception hierarchy, port consistency, typed domain models, config consolidation, etc.). 781+ tests pass, 0 regressions. The codebase has strong hexagonal architecture but **zero automated enforcement** — no linting, no type checking, no architecture tests, no pre-commit hooks, no CI for tests. Two boundary violations remain in `resilience/`.

This plan adds automated guardrails to prevent regression and enforce the architecture going forward.

---

## Phase 1: Fix 2 Resilience Boundary Violations

**Why**: `resilience/` must only import from `domain/`. Currently violates this with `infrastructure.ssl_hardening` and `adapters.dhan.auth`.

### 1A. `brokers/resilience/http_client.py` — Extract SSL hardening to callback

- **Remove**: `try: from brokers.infrastructure.ssl_hardening import create_pinned_session` (lines 26-29)
- **Add** `session_factory: Callable[[], requests.Session] | None = None` parameter to `__init__`
- **Logic**: `self._session = session_factory() if session_factory else requests.Session()`
- **Adapter migration**: `UpstoxHttpClient` and `DhanHttpClient` pass `session_factory=create_pinned_session` in their constructors (adapters are allowed to import infrastructure)

### 1B. `brokers/resilience/token_scheduler.py` — Replace DhanAuth with Protocol

- **Remove**: `if TYPE_CHECKING: from brokers.adapters.dhan.auth import DhanAuth`
- **Add** `TokenRefreshable` Protocol inline (or in `ports/auth.py`):
  ```python
  @runtime_checkable
  class TokenRefreshable(Protocol):
      def generate_token(self) -> str: ...
      @property
      def state(self) -> object: ...
  ```
- **Change** constructor: `auth: TokenRefreshable` instead of `auth: DhanAuth`
- DhanAuth already satisfies this structurally — no adapter changes needed

**Files**: `brokers/resilience/http_client.py`, `brokers/resilience/token_scheduler.py`
